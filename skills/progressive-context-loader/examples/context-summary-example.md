### 📋 Context Summary Card: Add Session Auto-Refresh Countdown

#### 1. Task Objective (WHY)
- **Goal**: When an active user session enters the renewal window, display a non-intrusive warning badge and trigger silent token refresh before expiry.
- **Reference**: `docs/proposals/auth-session-refresh.md` §2.1

#### 2. Domain Invariants (WHAT)
- **State Guard**: Only sessions in `AUTHENTICATED` state with valid refresh tokens may trigger auto-refresh.
- **Security Boundary**: Once a session transitions to `EXPIRED`, protected route access must be revoked immediately without silent retries.
- **Source**: `docs/domain/auth-lifecycle.md` §3.4

#### 3. Contracts & Code Truth (HOW)
- **Contract Definition**: `packages/auth-core/src/types/session.ts`
- **Core Interface**:
  ```typescript
  export interface UserSession {
    sessionId: string;
    userId: string;
    status: 'ANONYMOUS' | 'AUTHENTICATED' | 'REFRESHING' | 'EXPIRED';
    expiresAt: string;          // ISO 8601 string
    refreshThresholdSec: number; // e.g. 300 seconds
  }
  ```

#### 4. Applicable Conventions (CONVENTION)
- **Naming (`docs/conventions/naming.md`)**:
  - Hook filename: `useSessionExpiry.ts` (camelCase).
  - Component filename: `SessionExpiryBadge.tsx` (PascalCase).
- **Framework Standards (`docs/conventions/frontend.md`)**:
  - Timers must be wrapped in `useEffect` with proper timer cleanup (`clearInterval`).
  - No direct state mutations; state changes must propagate through the central AuthProvider.
  - UI copy must utilize localization keys (`t('auth.session_expiring')`), no hardcoded strings.
- **Error Handling (`docs/conventions/errors.md`)**:
  - Renewal failures must propagate as `AuthError.TokenRefreshFailed()` with standard error payloads.
